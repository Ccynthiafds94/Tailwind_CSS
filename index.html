A quick way to read a class: md:hover:bg-violet-700 means “at medium screens and up, when hovered, use a darker violet background.” Read it from left to right: when → what changes.

↔RESPONSIVE DESIGN

One page, every screen.

Tailwind starts with the small-screen style. Add a prefix to change it at larger screen sizes. The prefixed style applies at that size and above.

<h1 class="text-2xl md:text-4xl lg:text-5xl">
  Looks good on every screen
</h1>
Read it: small text by default → larger at medium → biggest at large.
What are the usual screen prefixes?

In the default Tailwind setup: sm: starts at 640px, md: at 768px, lg: at 1024px, xl: at 1280px, and 2xl: at 1536px. A project can customize these breakpoints.

◎INTERACTIVE STATES

Make buttons feel alive.

Put a state prefix before a utility to apply it only when something happens: hover, keyboard focus, press, or disable.

<button class="bg-violet-600
  hover:bg-violet-700
  focus-visible:outline-2
  active:scale-95
  disabled:opacity-50">
  Save changes
</button>
Accessibility tip: use focus-visible: so keyboard users can see where they are.
▦FLEXBOX & GRID

Arrange things without guessing.

Use Flexbox for a row or column of items. Use Grid when you want rows and columns together.

<div class="flex items-center justify-between">
  <span>Logo</span><button>Menu</button>
</div>

<div class="grid grid-cols-1 md:grid-cols-3 gap-4">
  <!-- three cards on wider screens -->
</div>
Remember: gap-4 adds space between items; it does not add space around the outside.
☾DARK MODE

Give your page a night mode.

Pair a normal color with a dark: version. Tailwind applies the dark variant according to the dark-mode strategy configured for your project.

<article class="bg-white text-slate-900
  dark:bg-slate-900
  dark:text-white">
  Works in light and dark themes
</article>
Tip: check your project’s dark-mode setting before expecting a toggle to control dark:.
⌁ARBITRARY VALUES

Need a one-off value? Use brackets.

Most of the time, use the built-in spacing and colors. When a design genuinely needs a specific value, square brackets let you write it directly.

<div class="w-[37px]
  bg-[#f5f0ff]
  grid-cols-[1fr_auto]">
  A custom width, color, and grid
</div>
Use with care: repeated one-off values are a sign to create a shared design token instead.
⌘COMPOSE & REUSE

Keep class lists understandable.

Group related utilities in a readable order, extract repeated UI into a component, and use group when a child reacts to its parent.

<a class="group flex items-center gap-3">
  <span>Read the lesson</span>
  <span class="transition group-hover:translate-x-1">
    →
  </span>
</a>
Why group? It lets a child respond when the parent link is hovered.
PUT IT TOGETHER

A responsive product card

This combines layout, spacing, responsive prefixes, color, and a hover state in one useful example.

<article class="group grid gap-4 rounded-2xl bg-white p-4 shadow-sm
  md:grid-cols-[140px_1fr] md:items-center
  hover:shadow-lg transition-shadow">
  <img class="h-40 w-full rounded-xl object-cover md:h-full"
       src="plant.jpg" alt="A small plant in a ceramic pot">
  <div>
    <p class="text-sm text-emerald-700">Easy care</p>
    <h2 class="mt-1 text-xl font-bold text-slate-900">Sunny the plant</h2>
    <p class="mt-2 text-sm leading-6 text-slate-600">
      A cheerful little plant for your desk.
    </p>
    <button class="mt-4 rounded-lg bg-emerald-700 px-4 py-2
      text-sm font-semibold text-white hover:bg-emerald-800
      focus-visible:outline-2">Add to cart</button>
  </div>
</article>

A COMMON BUILD-TIME SURPRISE

Keep class names complete.

When Tailwind builds your CSS, it scans files for class names. If you create a class by joining fragments, the scanner may not see the finished name:

// Avoid building class names from fragments
`bg-${color}-600`

Instead, map choices to complete class names so they can be found:

const colors = {
  violet: "bg-violet-600",
  mint: "bg-emerald-600"
};

WHEN YOU SHIP A REAL SITE

Use the right Tailwind setup.

This learning page uses Tailwind’s browser CDN to make examples quick to try. The CDN is handy for learning and prototypes, but Tailwind recommends a build setup for production.

  1. Install Tailwind for your framework or build tool.
  2. Build CSS as part of your app’s normal workflow.
  3. Check your browser’s developer tools for layout and contrast.

Tailwind v3 and v4 have different setup instructions. Follow the docs for the version your project actually uses.
